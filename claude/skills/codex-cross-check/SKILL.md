# Codex 교차 검증

## 쓸 수 있는지 먼저 확인한다

1. Codex 플러그인의 `codex-companion.mjs setup --json` 을 실행한다(`~/.claude/plugins/cache/openai-codex/codex/*/scripts/` 중 최신 버전).
2. `ready` 가 `true` 일 때만 진행한다. `false` 면 생략하고 이유(미설치·로그인 해제)를 알린다.
3. `python3 ~/.claude/skills/codex-cross-check/usage.py` 로 남은 사용량을 확인한다. 이 스크립트는 마지막 호출 기록을 읽으므로, 기록된 초기화 시각이 지났으면 초기화된 것으로 간주한다.
   5시간 창이 20% 미만이고 아직 초기화 전이면 초기화 시각을 알리고 기다릴지·범위를 축소할지·생략할지 사용자에게 질문한다. 독자 테스트도 같은 사용량을 사용하므로 함께 계획한다.
4. `ready` 가 `true` 여도 실제 호출에서 사용량·구독·인증 오류가 발생하면 사용할 수 없는 상태로 간주한다. 같은 호출을 반복하지 않는다.
5. 사용할 수 없을 때는 Codex 답을 임의로 작성하지 않는다. 상태, 확인한 명령, 실패 단계와 오류 요약, 이번 답에서 검증하지 못한 범위를 기록하고 단독으로 답한다.
6. 호출 옵션이 불확실하면 설치된 `codex-companion.mjs` 의 사용법 코드나 인자 처리 코드를 확인한다. `task --help` 는 실행하지 않는다. `task` 는 알 수 없는 인자를 요청문으로 전달해 Codex 작업을 실행한다.

## 진행

1. 내 답과 근거를 먼저 파일에 기록해 고정한다.
2. Codex 에는 내 결론을 제외하고 같은 자료·질문·출력 형식을 새 읽기 전용 작업(`task --fresh`)으로 전달한다. 모델은 지정하지 않는다(사용자의 Codex 설정). 사용자가 지정하면 따른다.
3. 읽어도 되는 곳과 읽지 않을 곳을 프롬프트에 명시한다. 비밀값이 들어 있는 설정 파일이 그 대상이다.
4. 두 답을 항목별로 대조한다. 불일치하는 곳은 양쪽 근거와 통합안을 전달해 같은 대화(`--resume-last`)로 다시 질의한다.
   `--resume-last` 는 같은 `--cwd` 의 가장 최근 작업을 이어받는다. 다시 질의하기 전에 `status` 로 가장 최근 작업이 이어서 질의할 검증인지 확인한다. 이어서 질의할 수 없으면 앞 요청·판정 원문·쟁점을 새 작업에 포함해 질의하고 그 사실을 보고에 기록한다.
5. Codex 의 반론을 검토해 내 답을 다시 확인한다. 타당하면 수용한다.
   Codex 가 제안한 대안 문장도 원문·코드와 대조한 뒤 수용한다. 근거가 없는 문장과 아직 결정하지 않은 것을 확정하는 문장은 수용하지 않는다.
6. 두세 차례 안에 합의되지 않으면 억지로 통합하지 않고 쟁점을 사용자 결정 사항으로 남긴다.
7. 오래 걸리는 호출은 Bash 백그라운드로 실행하고 무엇을 기다리는지 사용자에게 알린다. 출력은 파일로 리디렉션하지 않는다(전역 「교차 검증」).

## 보고

- 항목마다 소제목을 두고 차수 순서대로 기록한다. 각 차수에는 Claude 가 전달한 답·반론·통합안과 그에 대한 Codex 답을 함께 기록한다.
- 마지막에 최종안과 채택 근거를 기록한다. 어느 한쪽의 반론이나 변경 제안도 생략하지 않는다.
- 제안 문장은 표 칸이 아니라 인용으로 별도 제시한다.
- 두 답이 처음부터 일치한 항목은 묶어서 한 줄 근거로 기록해도 된다.
- 사용량이 부족해 반론 차수를 생략했으면 그 사실과 무엇을 직접 확인해 대신했는지 기록한다. 실행한 명령과 그 출력을 함께 기록한다.
- 마지막 줄에 Codex 의 남은 사용량을 기록한다. `python3 ~/.claude/skills/codex-cross-check/usage.py` 가 가장 최근 기록에서 5시간 창과 7일 창을 읽는다. 다음 검증을 언제 요청할 수 있는지가 이 값으로 결정된다.
