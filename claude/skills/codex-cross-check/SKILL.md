# Codex 교차 검증

## 쓸 수 있는지 먼저 확인한다

1. Codex 플러그인의 `codex-companion.mjs setup --json` 을 실행한다(`~/.claude/plugins/cache/openai-codex/codex/*/scripts/` 중 최신 버전).
2. `ready` 가 `true` 일 때만 진행한다. `false` 면 생략하고 이유(미설치·로그인 해제)를 알린다.
3. `python3 ~/.claude/skills/codex-cross-check/usage.py` 로 남은 사용량을 확인한다. 이 스크립트는 마지막 호출 기록을 읽으므로, 기록된 초기화 시각이 지났으면 초기화된 것으로 간주한다.
   5시간 한도가 20% 미만이거나 주간 한도가 5% 미만이고 아직 초기화 전이면 초기화 시각을 알리고 기다릴지·범위를 축소할지·생략할지 사용자에게 질문한다. 독자 테스트도 같은 사용량을 사용하므로 함께 계획한다.
   한도는 요금제에 따라 다르다. `usage.py` 가 한도 기간을 읽어 5시간 한도와 주간 한도를 구분한다.
4. `ready` 가 `true` 여도 실제 호출에서 사용량·구독·인증 오류가 발생하면 사용할 수 없는 상태로 간주한다. 같은 호출을 반복하지 않는다.
5. 사용할 수 없을 때는 Codex 답을 임의로 작성하지 않는다. 상태, 확인한 명령, 실패 단계와 오류 요약, 이번 답에서 검증하지 못한 범위를 기록하고 단독으로 답한다.
6. 호출 옵션이 불확실하면 설치된 `codex-companion.mjs` 의 사용법 코드나 인자 처리 코드를 확인한다. `task --help` 는 실행하지 않는다. `task` 는 알 수 없는 인자를 요청문으로 전달해 Codex 작업을 실행한다.

## 모델과 추론 수준을 사용자에게 먼저 확인한다

세션에서 Codex 를 처음 호출하기 전에 사용자에게 모델과 추론 수준을 질문한다. 교차 검증과 독자 테스트가 같은 선택을 사용한다.

- 질문에는 추천 모델, 추천 추론 수준, 추천 근거를 함께 제시한다.
- 근거는 OpenAI 의 모델 권장 문서를 질문할 때마다 다시 확인해 인용한다. 문서 내용은 바뀔 수 있다.
  - Codex 모델 안내: https://learn.chatgpt.com/docs/models
  - 모델 선택 안내: https://developers.openai.com/api/docs/guides/latest-model
  - 추론 수준 안내: https://developers.openai.com/api/docs/guides/reasoning
- 문서와 함께 대화 맥락(검증할 작업의 난도, 남은 사용량, 사용자가 앞서 고른 모델)을 근거로 기록한다. 문서를 확인하지 못했으면 그 사실을 밝힌다.
- 사용자가 고른 모델과 추론 수준은 `--model`·`--effort` 로 명시하고 그 세션의 Codex 호출에 계속 사용한다. 사용자가 변경을 요청하면 다시 질문한다.

## 진행

1. 내 답과 근거를 먼저 파일에 기록해 고정한다.
2. Codex 에는 내 결론을 제외하고 같은 자료·질문·출력 형식을 새 읽기 전용 작업(`task --fresh`)으로 전달한다. 모델과 추론 수준은 「모델과 추론 수준을 사용자에게 먼저 확인한다」에서 사용자가 고른 값을 `--model`·`--effort` 로 명시한다.
3. 읽어도 되는 곳과 읽지 않을 곳을 프롬프트에 명시한다. 비밀값이 들어 있는 설정 파일이 그 대상이다.
4. 두 답을 항목별로 대조한다. 불일치하는 곳은 양쪽 근거와 통합안을 전달해 같은 대화(`--resume-last`)로 다시 질의한다.
   `--resume-last` 는 같은 `--cwd` 의 가장 최근 작업을 이어받는다. 다시 질의하기 전에 `status` 로 가장 최근 작업이 이어서 질의할 검증인지 확인한다. 이어서 질의할 수 없으면 앞 요청·판정 원문·쟁점을 새 작업에 포함해 질의하고 그 사실을 보고에 기록한다.
5. Codex 의 반론을 검토해 내 답을 다시 확인한다. 타당하면 수용한다.
   Codex 가 제안한 대안 문장도 원문·코드와 대조한 뒤 수용한다. 근거가 없는 문장과 아직 결정하지 않은 것을 확정하는 문장은 수용하지 않는다.
6. 두세 차례 안에 합의되지 않으면 억지로 통합하지 않고 쟁점을 사용자 결정 사항으로 남긴다.
7. 오래 걸리는 호출은 Bash 백그라운드로 실행하고 무엇을 기다리는지 사용자에게 알린다. 출력은 파일로 리디렉션하지 않는다(전역 「교차 검증」).

## 보고

교차 검증 보고는 세션 최종 답변에 싣는다. Artifact 댓글 스레드처럼 크기 제한이 있는 곳에는 결론과 「전문은 세션 답변에 있다」만 기록한다. 이 경우 「세션에는 한 줄만」 안내보다 이 규칙이 우선한다. PR 댓글로는 게시하지 않는다(전역 「브랜치·PR 흐름」).

- 검토 항목에 번호를 붙인다. 보고하기 전에 검토 항목 수와 보고한 항목 수가 같은지 대조한다.
- 항목마다 주고받은 내용을 요약해 기록한다. 대화 원문이 아니라 요약이다.
  - Codex 에 전달한 질문의 요지
  - 차수마다 Claude 판단의 요지와 Codex 답의 요지. Codex 답의 핵심 문장은 인용한다.
  - 두 판단이 갈렸으면 Claude 안과 Codex 안을 나란히 기록하고, 어느 안으로 결정했는지와 그 근거를 기록한다. 사용자가 이 기록만 보고 결정을 뒤집을 수 있어야 한다.
  - 최종안과 반영 여부
- 두 답이 처음부터 일치한 항목은 한 줄로 묶어도 된다. 그때도 Codex 결론은 인용한다.
- 제안 문장은 표 칸이 아니라 인용으로 별도 제시한다.
- 사용량이 부족해 반론 차수를 생략했으면 그 사실과 무엇을 직접 확인해 대신했는지 기록한다. 실행한 명령과 그 출력을 함께 기록한다.
- 마지막 줄에는 `python3 ~/.claude/skills/codex-cross-check/usage.py` 출력을 그대로 붙인다. 이 출력에는 모델, 추론 수준, 한도별 남은 사용량이 들어 있다. 다음 검증을 언제 요청할 수 있는지가 이 값으로 결정된다.
